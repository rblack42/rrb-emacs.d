For many years, I taught college-level courses in Computer Science. I taught many students their first course in programming, and tried to get them started learning the basic tools they would need to be comfortable with during their careers. Of course a programmer's text editor was one of those tools. I chose the editor I used for most of my career, Vim, not because it was the best one available, but because it could be used on just about any machine they would want to program. Well, not exactly all machines. I taught an introductory computer architecture course, where they learned how to program microcontrollers.

Getting started with Vim is fairly easy, and I still feel it is a good first editor for students to learn. But there are other editors available, so I always asked myself if I should switch to something else. These days, a lot of schools introduce students to Visual Studio Code, which is a nice *Integrated Development Environment (IDE)*, but I prefer that my students know exactly how their programs are put together so they run. IDEs tend to hide everything behind a set of visual point-and-click tools. My theory is that they should learn a good IDE after they know what is going on. Plus, there is no guarantee that the IDE they learn in school will be the one they use on the job afterwards.

In this note, I will introduce Emacs to beginners. Emacs has something of a bad reputation as a tool with a steep learning curve that you have to get through before you can use it effectively. I am going to try to get you using it immediately, then tune it so it becomes a much more comfortable and powerful tool. I could do this using Vim as well, but I want to show beginners a different programming language from the one they are probably learning. This one, Lisp, happens to be one of the oldest languages around. It looks very different from "conventional" languages, but it is very powerful. In fact most of what happens in Emacs is crafted using Emacs-lisp, which is a dialect of Lisp tuned to the needs of an editor.
